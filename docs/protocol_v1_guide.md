## 1. 数据划分：协议 v1

### 1.1 为什么要重新划分

原来的数据集只有 `train_index.txt` / `test_index.txt`，测试集是 160 个随机位置。问题有两个：

1. **它被反复用来挑方案。** 每一轮都在这 160 个位置上评估，再按结果决定下一轮做什么，所以它其实是验证集。在它上面报出的数字对"挑出来的那个方案"偏乐观。
2. **它只测插值。** 随机抽出的位置离最近的训练位置中位只有 0.23 m，测不到"离训练数据远了会怎样"。

### 1.2 五个集合

| 集合 | 位置数 | 离最近训练位置（中位） | 含义 |
| --- | --- | --- | --- |
| `train` | 467 | — | 只用来训练 |
| `val_random` | 59 | 0.23 m | 验证·插值：旧 160 个留出位置中（去掉落在测试盒子、验证段和缓冲带里的）随机的一半；另一半回到训练集 |
| `val_segment` | 61 | 1.74 m | 验证·外推：一段路线（y > −1、1 < x < 3） |
| `test_interp` | 46 | 0.25 m | **封存**·插值：从没被评估过的位置里抽 10 % |
| `test_region` | 101 | 1.87 m | **封存**·外推：空间盒子 x > 4、y < −7 |
| `dropped` | 66 | — | 不用：缓冲带、盒子里旧测试集评估过的位置、近重复 |

- **缓冲带**：验证段和测试盒子外围 0.5 m（xy 平面）内的位置不进训练集，否则"外推"会被紧挨着的训练位置稀释。
- **近重复**：两个位置相距 < 5 cm 时去掉一个（这次去掉了 2 个训练位置）。
- 每个位置的 4 个面（4 张图）永远整体进同一个集合。
- `--eval-set val` 同时评 `val_random` 和 `val_segment`，两者也可以单独评。

### 1.3 封存怎么实现

- `rrf_gsplat/protocol.py` 的 `eval_names()` 读到 `test_interp` / `test_region` 时，没有 `--final-test` 就直接报错退出。
- 带了 `--final-test`，每次读取都追加一行到 `rrf_gsplat/protocol_v1/test_access.log`。**这个文件目前不存在**，也就是测试集还没被任何人读过。
- 阶段 4 的规则：选定方案后在测试集上只跑一次；不在 train + val 上重训。

### 1.4 位姿指纹（为什么数据集要"对得上"协议）

协议只是一组名字（`00013`、`00014`……），而不同数据集的同一个名字必须是同一个接收位置、同一个朝向。`protocol.images_digest()` 把每张图的名字、四元数、接收点坐标舍入到 1e-6 后做摘要，`check_dataset()` 在每个脚本启动时核对。所有用 `--poses-from` 生成的数据集（MVDR、float64 MVDR、Bartlett、POW、MULTI、APS）指纹都是 `4fb157d4…`。

用逐字节的摘要不行：`--poses-from` 重写的 `images.txt` 与原文件在第 15 位小数上不同。

### 1.5 怎么用

七个脚本都有同样三个开关：`--protocol rrf_gsplat/protocol_v1`、`--eval-set val|val_random|val_segment`、`--final-test`。
它们是 `train_rrf.py`、`mvdr_peaks.py`、`diag_train_fit.py`、`eval_baselines.py`（rrf_gsplat/），以及 `t4_score.py`、`t4_baselines.py`、`t6_incoherent_mvdr.py`（sionna_port/）。
不带 `--protocol` 时行为与以前完全一样（仍读 `train_index.txt` / `test_index.txt`），所以旧轮次都可以复现。

## 2. 评估指标

### 2.1 主峰方向误差与 ≤ 1°

一张谱的主峰 = 数值最大的像素，它对应一个方向（主路径的来向）。**主峰方向误差** = 预测谱的主峰方向与真值主峰方向之间的夹角（度）。报两种统计：中位数，以及误差 ≤ 1° 的视图占比。

为什么不用 PSNR：今天之前所有"颜色模型"（SH 阶数、锐瓣、CNN 着色头、P7）都是像素指标涨、峰不动。谱的用途是找路径方向，像素平均掩盖了这一点。

### 2.2 distinct 视图（已定为主指标的口径）

**定义**：真值谱的最强峰与它的"最强对手"（离它 ≥ 3° 的另一个局部极大，且在 20 dB 以内）相比，至少高 1 dB，这张视图就算 distinct；如果 20 dB 以内没有对手，也算。

**为什么需要它**：有些视图（多是弱的漫散射面）上两个峰几乎一样高，argmax 落在哪一个带有偶然性。证据是同一场景独立抽样两次（只换射线追踪的采样格点），主峰 ≤ 1° 的一致率在全部视图上是 86 %，在 distinct 视图上是 98 %。也就是说，全部视图的 ≤ 1° 里混着约 14 % 连"真值对真值"都对不上的噪声。

代码：`mvdr_peaks.py` 与 `diag_train_fit.py` 在原有字段之外输出 `main_peak_angle_deg_distinct` / `distinct_*`，原有字段不变。

### 2.3 波束增益损失（level 3，选择指标之二）

问的是：**如果真的把阵列波束对准模型预测的主峰方向，在真实信道上损失多少功率？**

1. 真实信道用每张视图的抽头协方差 R_coh 表示。`t6_incoherent_mvdr.py` 用生成 MVDR 数据集时同样的场景、种子和 tr38901 阵列重解这张视图的路径，把 0.1 ns 抽头作为快照，求 R = Σ x_l x_lᴴ。它同时核对重解能复现存储的真值：float64 数据集上最大差 0.005 dB。
2. 对每个像素方向 u 求匹配波束的接收功率 q(u) = a(u)ᴴ R a(u) / |a(u)|²，a(u) 含单元方向图。这是一张 Bartlett 图。
3. 波束增益损失 = max q − q(预测主峰方向)，单位 dB。0 表示对准了最好的波束。

参照值：对准真值 MVDR 主峰本身损失 0.02–0.04 dB（指标校准良好）；对准 APS 真值主峰损失 0.55 dB（APS 的峰是单条路径的方向，不一定是 11° 宽的阵列波束里功率最大的方向）；APS 第二次独立抽样 0.60 dB（噪声底）。

它比方向误差更"宽容"：近并列的两个峰对准哪一个损失都小。验证集的 R_coh 存在 `output/rrf/t4_rt_cov_val_all.npz`（480 张，29 MB），在 `t4_score.py --cov` 里用。

### 2.4 其他报了但不作选择依据的

- **真峰处误差**：预测谱在真值主峰那个像素上的值减真值（dB），看电平对不对。
- **前 3 峰检测率**：真值前 3 个峰（相距 ≥ 3°）各自 1.5° 内有没有预测的局部极大。注意：场的谱很"疙瘩"（一张图几十个局部极大），会虚抬这一项。
- **假峰率**：预测的前 5 个峰中，附近没有真值峰的比例。

## 3. 查表基线（"查表"指什么）

三种方法都不训练任何模型，只是把训练集里已有的真值谱查出来用。代码在 `sionna_port/t4_baselines.py --which nn,idw,const`，只用协议里的训练位置。

| 方法 | 怎么预测一张视图 |
| --- | --- |
| **NN**（最近邻） | 找离该位置最近的训练位置，复制它**同一朝向**那一面的真值谱 |
| **IDW k**（反距离加权，k = 2 / 4 / 8） | 取最近的 k 个同朝向训练位置，谱转成线性功率，按 1/距离 加权平均，再转回 dB |
| **常数** | 每个朝向一张固定的谱：所有训练视图逐像素取 dB 中位数，与位置无关 |

为什么要它们：一个辐射场如果连"抄邻居的真值"都赢不了，就不能说它学到了场。常数是下限，任何利用了位置信息的方法都必须越过它。

## 4. 标签（训练目标）的种类

| 目标 | 数据集 | 每个像素是什么 | 对路径可加？ | 带仪器？ | 用在哪里 |
| --- | --- | --- | --- | --- | --- |
| MVDR（存储） | `3dgs_MVDR_100_gpct` | 10×10 阵列的 MVDR 伪谱，complex64 计算 | 否 | 是（阵列 + tr38901） | round 45 锚点 |
| MVDR（float64） | `3dgs_MVDR_100_f64_gpct` | 同上，float64 计算（弱方向不再是舍入噪声） | 否 | 是 | round 50 锚点 |
| Bartlett | `3dgs_CBFF_60_gpct` | √(aᴴRa)，抽头当快拍 | 是 | 是 | round 54 |
| **APS** | `3dgs_APS_60_gpct` | 每条路径的功率按到达角溅射（σ = 1°） | 是 | **否**（iso） | 阶段 2、M3 |

"带仪器"是指谱里含有阵列和单元方向图的效应。APS 去掉了它们，只剩"功率从哪个方向来"，是场最应该能表示的量。

### 4.1 APS 的生成细节（`generate_dataset.py --spectrum APS`）

- **溅射**：每个接收位置在整个球面上做一张等距柱状图（1/3° 一个像素），每条路径的功率 |a|² 以 σ = 1° 的高斯核加到它的到达角上，再切出 4 个 90° 的面。方位角在 ±180° 处环绕（旧的溅射函数是截断的，会在 180° 面中间堆出假峰）。
- **iso 接收方向图**（`--rx-pattern iso`）：Sionna 的路径幅度已经乘上了接收单元方向图，而投影类数据每个位置只在 yaw = −90° 解一次再切 4 个面。用 tr38901 的话，背面会被压低约 30 dB，阶段 3 的算子还会再乘一次方向图。
- **软地板**：存 10·log10(P + N0)，而不是硬截断。N0 全数据集只取一个值 = 各视图最大值的中位 − 40 dB = −143.98 dB。不能每张图各取一个 N0，那等于逐张归一化，会抹掉绝对电平。
- **dB 存、dB 训**：线性功率跨十几个数量级，`load_views` 以前把单通道浮点存成 float16 会毁掉它。现在单通道一律 float32。
- **采样**：每个位置独立解 4 次，每次 4M 条射线，线性功率取平均（`--aps-repeats 4`）。一次解 16M 显存不够。
- **两个修掉的坑**：
  - Sionna 的 `max_num_paths_per_src` 默认 1e6，超出时静默截断。16M 采样时它丢掉了强路径，两个种子一样空，判据却显示"全过"。现在显式设为 1e7。
  - Dr.Jit 的显存缓存会越积越多，全量生成到第 100 个位置左右会 OOM。现在每次解之后清一次缓存。
- **检查**（`sionna_port/check_aps.py`）：
  - 两种子 smoke：命中像素的种子间 RMSE 0.38 dB，面与面接缝 0.00 dB。主峰 ≤ 1° 一致率 72.9 %，没过 90 % 的判据，原因就是 §2.2 的近并列峰。
  - 单路径解析对照：已知方向的一条路径进去，经溅射、切面、argmax，再用数据集自己的 COLMAP 位姿回到世界系，最大误差 0.40°。

## 5. 容量基准与阶段 2 的门

### 5.1 容量基准是什么

用 160 个训练位置（训练列表上均匀取、两端都在）训练 3000 步，然后**在这些训练视图上**打分。

它回答"场连自己见过的视图都拟合不了吗"，把"表示能力不够"（欠拟合）和"泛化不了"分开。rounds 51–56 都用它，所以新方案可以直接和旧数字比。代码：`train_rrf.py --max-train-views 640` + `diag_train_fit.py --train-subset 640`。

### 5.2 门与结果

门是跑之前写死的（power 模式，≤ 1°）：≥ 50 % → 做阶段 3（把阵列处理作为已知算子接在渲染后面）；≤ 30 % → 阶段 3 取消，转 M3；两者之间只做阶段 3 的 smoke。

结果：power 26.8 %（distinct 29.1 %），db 18.5 % → **≤ 30 %，阶段 3 取消**。

怎么理解：像素拟合很好（训练 RMSE 1.9 dB），但峰的方向放错了；在验证集上，预测谱的角展宽是 34°，真值 14°。

**更正**：之前说过"场在真值主峰处低约 13 dB，峰被抹平"，这是截峰（§6）造成的假象。被截峰的视图上，训练目标在上界处是平的，场也到不了上界以上，所以误差 ≈ 上界 − 真值最大值（中位约 −15 dB；和训练时实际看到的目标比只差 −0.2 dB）。没被截的视图上真峰处只低约 1.9 dB。−13.4 dB 是两组混在一起的中位数。峰的电平基本对，错的是方向。

结论不变：APS 可加、没有阵列、也没有地板边缘，场照样放不对峰，所以问题不在标签（M1），在高斯的表示和放置（M3）。

## 6. 截峰：一个早已存在的混淆因素

`renormalize.py --norm global-pct` 取全体像素的 1–99.9 百分位作训练范围，`train_rrf.py` 把训练目标夹在这个范围内。最大值高于上界的视图，训练目标的峰顶就是一块平台。

| 数据集 | 峰被截的视图 | 超出上界多少（中位） |
| --- | --- | --- |
| APS | 25 % | 14.4 dB |
| MVDR（两种） | 16–17 % | 4.6–5.4 dB |
| Bartlett | 7 % | 3.5 dB |

被截的几乎全是朝向发射机的那一面（最亮的视图）。它**不是**容量失败的原因：被截的视图反而拟合得更好，没被截的单独算就只有 24.5 %。但它让这些视图上的电平指标偏低，平台上的 argmax 也不唯一。以后的新表示应该用不截峰的范围（`renormalize.py --pct 1 100` 或 `--range`），或者分开报。

## 7. 阶段 1 的要点（完整表在笔记 §5）

- 选择指标上，**没有任何场赢过查表**。最好的场是 P7：方向中位 5.09°、波束增益损失 1.93 dB；NN 是 2.39° / 0.63 dB；IDW-8 的损失最低，0.60 dB（P90 4.3 dB）。
- P7 比 SH3 好是真的（超出种子范围），而且几乎都在外推段：5.6° 对 11.6°。
- "离训练越远，场越可能赢"不成立：外推段上 SH3 是 11.6°，NN 是 4.2°。
- 原定"最小有效差 0.3°"太小：SH3 三个种子在验证集上的方向中位就相差 1.8°。读结果时用实测的种子范围。
- 3GPP InH 和几何 LOS 的数字引自 T4（旧留出集），没有重跑。

## 8. M3 放置 oracle

### 8.1 想回答的问题

场的峰出现在"某个高斯投影到的地方"。视觉重建把高斯放在有视觉纹理的地方，而无线电能量来自反射点、漫散射热点。**如果把高斯放在真正的能量来源处，容量基准能不能过？**

这是 oracle：用了射线追踪才有的信息（每条路径的交互点），只用来诊断"放置"是不是瓶颈，不是可部署的方法。

### 8.2 发射点怎么来（`sionna_port/path_emitters.py`）

1. 对每个选中的接收位置，用 APS 数据集同样的配置和第一次解的种子重解路径。
2. 每条路径取它的交互点（一次反射或散射的位置；直射路径取发射机位置），配上它的功率 |a|²（与 APS 溅射的是同一个量）。
3. 以 5 cm 为边长划体素，每个体素累加功率并记功率加权的中心。
4. **按面（方位扇区）分别保留**最强的体素，直到覆盖该扇区 90 % 的功率，每个位置最多 8000 个。最初按整个位置保留 90 %，背面那些只有弱路径的面的峰全被丢掉了。
5. 所有位置的并集就是发射点，位置取功率加权的中心。

### 8.3 发射点怎么渲染（`train_rrf.py --emitters`，只支持 `--mode power`）

- 每个发射点是一个各向同性的小高斯（半径 2.5 cm），**单独光栅化一遍**，结果以线性功率**加到**场的渲染上，再转 dB。
- 视觉高斯不遮挡它们，所以这是最宽松的 oracle：如果连这样都不行，更严格的版本也不会行。
- 位置、大小、不透明度都固定，只有颜色（SH3，也就是每个方向发出多少功率）可训练。
- **亮度**：v = 1.5 · sigmoid(SH)，功率 = 10^(v · 量程 / 10) − 1。v → 0 时功率 → 0，关掉的发射点不加任何功率；而且没有硬裁剪，梯度永远不为 0。
- **不透明度**固定为 0.05：高于 gsplat 的 alpha 截断（1/255，低于它的高斯会被光栅化器直接跳过），又足够小，使发射点之间近似直接相加。
- 初值 v = 0.02：训练开始时模型与原来几乎一样（smoke 实测最大差 0.005 dB）。发射点的学习率是视觉高斯的 10 倍（`--emitter-lr-mult`），不然 3000 步内从暗到亮走不完。

**为什么是这样（两次踩坑）**：

1. 最早的版本颜色初值正好压在地板上。颜色被裁剪在 [0, 1]，边界上梯度为 0，smoke 的 S2 查出发射点完全没有梯度。
2. 改成"比地板高 0.01"之后，smoke 的 S1–S3 都过了，但**第一次全量运行里 97 % 的发射点还是死了**：
   - 训练初期整张图偏亮，所有贡献都被往下推，发射点的值很快落到 0 以下被裁剪；
   - 可训练的不透明度则衰减到 1/255 以下，被光栅化器跳过。
   这次运行无效（留档为 `output/rrf/m3/*_deadv1`）。当时的 smoke 只检查了第一步的梯度，所以没抓到，于是加了 S5 存活检查。现在的参数化就是为了去掉这两个死区。

### 8.4 smoke（12 个分层位置：容量列表两端、有平视图的位置 460、最弱位置 463）

### 8.5 全量运行（`rounds/win_m3_oracle.sh`、`win_m3_seeds.sh`）

与阶段 2 容量基准完全相同（160 个位置、3000 步、power 模式），只多了这 160 个位置的发射点（89,247 个；峰复现检查 91.6 %）。

跑之前写下的读法（主指标 distinct ≤ 1°，不加发射点时 29.1 %）：

- **≥ 50 %**：缺的是放置 → 走 P4 正式版（用路径监督去学能量放在哪）。
- **≤ 30 %**：放在真实位置也救不回峰 → 需要每位置的成分（每位置潜变量，或显式路径集）。
- **两者之间**：两方面都有影响。

**要注意**：发射点被所有位置共享，颜色的视角依赖只有 SH3（约 45° 的角分辨率）。一个反射点应该只对镜面方向附近的接收位置亮，SH3 表达不了这么尖的开关。所以这个 oracle 测的是"放对位置 + 共享的 SH3 颜色"。如果不到 30 %，结论是"共享的场表示不够"，不是"放置无关紧要"。

结果（种子 0）：distinct ≤ 1° **30.4 %**（全部视图 28.3 %），不加发射点是 29.1 %（26.8 %）。训练 PSNR 23.80 → 24.85。发射点层确实在起作用（P99 像素贡献 8.6 dB），但主峰方向几乎没动。

30.4 % 比 30 % 的线只高 0.4 个点，比基线高 1.3 个点，与一个种子的波动同量级。所以不解读单次结果，有、无发射点各补 2 个种子，按均值读。

### 8.6 结论（三个种子）

| | 种子 0 / 1 / 2（distinct ≤ 1°） | 均值 | 全部视图均值 | 训练 PSNR |
| --- | --- | --- | --- | --- |
| 不加发射点 | 29.1 / 22.2 / 23.9 % | 25.1 % | 24.2 % | 23.8 |
| 加发射点 | 30.4 / 25.6 / 25.2 % | **27.1 %** | 25.7 % | 24.9 |

- **≤ 30 %：放对位置也不够。** 每个种子都只提高 1–3 个点。按事先的读法，下一步转向每位置的成分（每位置潜变量，或显式路径集），不走 P4。
- **容量基准的种子波动比原以为的大**：同一配置在 22–29 % 之间，原先以为只有 ±1 点。阶段 2 的门用的种子 0 恰好在高端，三种子均值 25.1 %，门的结论不变。以后容量基准至少跑 3 个种子。
- **为什么放对了还不够**：12 个位置时，发射点把 distinct ≤ 1° 从 35 % 提到 53 %；160 个位置时几乎不动。发射点在位置少时有用，位置一多就没用了。这指向"很多位置共享同一组颜色"是瓶颈，与上面的注意事项一致。


### 8.7 第二轮：发射点 + 随位置变化的颜色（smoke 已过，全量待定）

**想法**：第一轮说明，只放对位置不够，因为共享的 SH3 颜色没法让一个反射点"对这些接收位置亮、对那些暗"。第二轮让发射点的亮度也能随接收位置变化，也就是把 P7 用在发射点上。

**做法**（`train_rrf.py --emitters … --em-pcolor 8`）：
- 每个发射点多一个 8 维潜变量 z。
- 一个共享的小 MLP 输入 [z，从接收点看它的方向，接收位置的傅里叶特征]，输出加到这个发射点亮度的 logit 上（乘以 4，这样开或关一个发射点只需要量级为 1 的输出）。
- MLP 最后一层初始为 0，所以训练开始时与只有发射点的模型逐位相同。
- 视觉高斯保持普通的 SH3。

**smoke 判据与结果**（`check_emitters.py --em-pcolor 8`，判据跑之前写下）：

| 检查 | 结果 |
| --- | --- |
| S1：与只有发射点的模型逐位相同 | 最大差 0（通过） |
| S2：第二步起，潜变量和 MLP 每一层都有梯度 | 通过 |
| S3：loss 下降；S5：没有发射点的梯度恰为 0 | 通过 |
| 每步耗时（只报告） | 25.2 ms，只有发射点时 24.2 ms |
| S4：12 个位置上 distinct ≤ 1°（只报告） | 不加发射点 35.3 %，只加发射点 52.9 %，发射点 + 随位置颜色 61.8 % |

全量运行的方案和读法在 §8.8。

### 8.8 第二轮全量：方案与读法（跑之前写下，2026-09-24）

同一个容量基准（160 个位置、3000 步、power 模式），每组 3 个种子，主指标是 distinct ≤ 1° 的三种子均值：

| 组 | 配置 | 作用 |
| --- | --- | --- |
| A | 发射点 + `--em-pcolor 8` | 要检验的组合：放对位置 + 随位置开关 |
| B | 不加发射点，视觉高斯 `--pcolor 8` | 对照：只有随位置颜色、不放对位置，在 APS 上能到多少 |
| 已有 | 普通 25.1 %，只加发射点 27.1 % | 第一轮 |

读法：

- **A ≥ 50 % 且 B < 30 %**：配方就是"能量放对位置 + 随位置开关"。oracle 的放置用了射线追踪，下一步要学会放置（P4 式的路径监督）。
- **A ≥ 50 % 且 B ≥ 50 %**：随位置颜色单独就够，放置不是必需的，走 P7 类模型。
- **A ≤ 30 %**：放对位置加随位置开关也不够，转向显式路径集。
- **A 在 30–50 % 之间**：两方面都有影响，按 A、B 与第一轮的差值再定。

## 10. 名词表

| 名词 | 意思 |
| --- | --- |
| APS | angular power spectrum，角功率谱：各方向来的功率，不经过阵列处理 |
| MVDR / Bartlett (CBF) | 两种阵列波束形成谱。MVDR 分辨率高但对路径不可加；Bartlett 可加但峰宽约 11° |
| R_coh / R_inc | 抽头协方差：相干的（同一抽头内的路径先相加）/ 非相干的（每条路径各算各的） |
| N0 | APS 的软地板功率，全数据集一个值 |
| gpct | `renormalize.py --norm global-pct`：全数据集 1–99.9 百分位作为训练范围 |
| 容量基准 | 160 个训练位置、3000 步、在训练视图上打分（§5.1） |
| distinct 视图 | 真值主峰比最强对手高 ≥ 1 dB 的视图（§2.2） |
| 噪声底 | 同一场景独立抽样两次之间的差，任何预测器在这个目标上都不可能比它更好 |
| M1 / M3 | 峰丢失的两种机制假设：M1 = 目标对路径不可加；M3 = 峰的位置由高斯放在哪里决定（`docs/tech_paths.md`） |
| P1 / P4 / P7 | 技术路径编号：P1 = 渲染功率后接已知的阵列算子（即阶段 3）；P4 = 用射线追踪的路径做监督；P7 = 随接收位置变化的颜色 |
| oracle | 借用了部署时拿不到的信息（这里是真实路径）的诊断实验，只回答"如果知道了会怎样" |
| smoke | 缩小规模、保留结构的先行测试，判据事先写好（见项目 CLAUDE.md） |
